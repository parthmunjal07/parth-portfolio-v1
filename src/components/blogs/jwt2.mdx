### Why Authentication?

Authentication acts as your application's digital bouncer. We need it to verify user identities, protect sensitive data, and ensure only authorized people can perform specific actions.

### Stateless Authentication Explained

Traditional apps use "sessions" where the server saves a record of your login in a database. **Stateless authentication** removes the database lookup. Instead, the server hands you a cryptographically signed "VIP pass." It doesn't remember you; it just mathematically verifies its own signature on your pass whenever you make a request.

### What is a JWT?

A **JSON Web Token (JWT)** is the industry standard for that VIP pass. It is a self-contained, URL-safe string (`xxxxx.yyyyy.zzzzz`) that carries everything the server needs to identify you.

### Structure of a JWT

*   **Header (**`xxxxx`**):** The envelope. It simply declares the token type (JWT) and the mathematical algorithm used to secure it (like HMAC SHA256).
    
*   **Payload (**`yyyyy`**):** The contents. It holds the "claims," such as your user ID, role, and the token's expiration time. **Crucial Rule:** This is readable text, *not* encrypted. Never put passwords or secrets here.
    
*   **Signature (**`zzzzz`**):** The wax seal. The server creates this by combining the Header, Payload, and its own private **Secret Key** through a math formula. If anyone alters the Payload, the signature breaks, and the server rejects the tampered token.

### The Login Flow

1.  **Request:** The user submits their username and password.
    
2.  **Verification:** The Node.js server checks the database to confirm the credentials match.
    
3.  **Creation:** The server generates a JWT, placing the user's ID in the payload and signing it with its Secret Key. It sends this token to the user.
    
4.  **Storage:** The user's browser securely saves the token (usually in an `httpOnly` cookie or `localStorage`).
    

* * *

### Protecting Routes & Sending the Token

To access restricted areas (like an account dashboard), the browser must present the JWT on every request. Standard practice is to send it in the HTTP headers like this: `Authorization: Bearer <your_jwt_token_here>`

### Middleware Validation Lifecycle

When you request a protected route in Node.js, middleware handles the verification before letting you in:

1.  **Interception:** The middleware pauses the incoming request.
    
2.  **Extraction:** It grabs the JWT from the `Authorization` header.
    
3.  **Verification:** The server uses its Secret Key to check the signature and verifies the token hasn't expired.
    
4.  **Decision:** If invalid or tampered with, the server instantly rejects it (`401` or `403` error). If valid, it decodes the payload, attaches the user data to the request, and lets the user through.
